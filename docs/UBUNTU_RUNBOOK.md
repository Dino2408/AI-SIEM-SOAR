# Ubuntu Runbook — Integrated SIEM/SOAR

## Architecture

Wazuh is the central SIEM/XDR layer. Suricata produces EVE JSON telemetry. The project-owned AI Analysis Module consumes Wazuh alerts, calls Ollama for bounded reasoning, applies a deterministic policy gate, and can submit allowlisted low-impact playbooks to Shuffle. High-impact response remains human-gated.

Wazuh's Docker deployment is kept from upstream rather than reimplemented. The project overlays only the manager image and integration configuration.

## Prerequisites

Ubuntu Server 22.04/24.04, Docker Engine, Docker Compose v2, Git and at least 16 GB RAM for the combined lab stack. Wazuh's current single-node Docker documentation lists 4 CPU cores, 8 GB RAM and 50 GB disk as minimums for the Wazuh stack alone. The Docker host also needs vm.max_map_count=262144.

## Configure

Copy .env.example to .env and set OLLAMA_MODEL to the exact local model tag. SURICATA_INTERFACE must match the host interface visible to the Suricata host-network container. SHUFFLE_WEBHOOK_URL is optional until a Shuffle webhook workflow is created.

For the first smoke test, OLLAMA_MODEL may be empty. The AI service returns BLOCKED rather than fabricating an analysis.

## Start

    chmod +x scripts/*.sh docker/wazuh-ai-integration/*
    ./scripts/ubuntu_bootstrap.sh

The bootstrap fetches pinned Wazuh Docker v4.14.8 and the Shuffle repository, builds the project-owned containers, generates Wazuh certificates, and starts the stacks.

## Verify

    curl http://127.0.0.1:8080/health
    ./scripts/stack_smoke_test.sh

Wazuh dashboard is available on https://SERVER_IP using the credentials generated by the upstream Wazuh deployment. Shuffle is normally exposed on its configured frontend port.

## Ollama

Default mode uses Ollama installed on the Ubuntu host. This avoids forcing the local 8 GB GPU into a second container runtime.

If the Docker NVIDIA runtime is correctly configured, the repository also contains an optional local-ollama Compose profile:

    docker compose -f docker/docker-compose.yml --profile local-ollama up -d ollama

## Suricata

The default Suricata container uses host networking and requires NET_ADMIN, NET_RAW and SYS_NICE. Set SURICATA_INTERFACE to the interface that should be inspected.

The Suricata EVE JSON file is shared with the Wazuh manager. Wazuh supports JSON localfile collection and documents the Suricata EVE integration pattern.

## Shuffle

Create a Shuffle workflow with a Webhook trigger and set its URL as SHUFFLE_WEBHOOK_URL. When Shuffle is exposed on the Ubuntu host, use host.docker.internal in the URL from the AI container, for example:

    http://host.docker.internal:3001/api/v1/hooks/webhook_<ID>

Start with a reversible workflow that records the event. Only then add controlled lab actions.

## End-to-end path

Suricata -> EVE JSON -> Wazuh -> custom-ai Integrator -> AI Analysis Module -> policy gate -> Shuffle webhook -> approved workflow.

Endpoint Wazuh agents can independently send host telemetry to the same Wazuh manager.

## Safety gates

The AI module does not expose shell execution. Evidence is constructed from fields actually present in the Wazuh alert. High-impact actions such as host isolation or account disabling are never executed autonomously. All decisions are audited.

## Stop

    ./scripts/stop_stack.sh

Stopping containers does not delete persistent volumes.
